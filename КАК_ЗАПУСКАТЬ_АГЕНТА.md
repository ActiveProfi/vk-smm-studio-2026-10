# Как запускать агента

## 1. Подготовьте входные данные

Откройте файл:

- `contracts/agent-input-template.json`

И заполните его своими данными:

- тип поста;
- материалы;
- источник;
- тон;
- нужен ли CTA;
- какой нужен визуал.

## 2. Если хотите только собрать запрос без отправки

Запустите:

```powershell
py -3 run_agent.py
```

После этого появятся файлы:

- `output/final-user-message.txt`
- `output/claude-request.json`

## 3. Если хотите отправить запрос сразу в KIE

### Вариант А. Через `.env`

1. Скопируйте `.env.example` в `.env`
2. Впишите свой `KIE_API_KEY`
3. Запустите:

```powershell
py -3 run_agent.py --send
```

### Вариант Б. Через переменную среды в PowerShell

```powershell
$env:KIE_API_KEY="ваш_ключ"
py -3 run_agent.py --send
```

## 4. Что создается после отправки

Если запрос успешно отправлен, появятся ещё файлы:

- `output/claude-response.json`
- `output/claude-answer.txt`

## 5. Как запускать генерацию картинки

Если Claude выбрал `image`, можно сразу отправить картинку:

```powershell
py -3 run_agent.py --send --send-image
```

## 6. Как запускать генерацию видео

### Вариант 1. Автовыбор видеомодели

```powershell
py -3 run_agent.py --send --send-video
```

Скрипт сам попробует:

- понять, какая видеомодель лучше подходит;
- если в ролике нужен текст в кадре, сначала сделать base image через `Nano Banana Pro`;
- потом использовать эту картинку как основу для видео.

### Вариант 2. Принудительно выбрать видеомодель

#### `Veo`

```powershell
py -3 run_agent.py --send --send-video --video-provider veo
```

#### `Hailuo`

```powershell
py -3 run_agent.py --send --send-video --video-provider hailuo
```

#### `Kling 3.0`

```powershell
py -3 run_agent.py --send --send-video --video-provider kling
```

## 7. Полезная команда для просмотра полного собранного запроса

```powershell
py -3 run_agent.py --print-message
```

## 8. Важно

- Не храните настоящий API-ключ в коде.
- Не отправляйте `.env` другим людям.
- Если ключ когда-то попадёт не туда, его лучше сразу перевыпустить в KIE.

## 9. Месячная цепочка VK

Основной маршрут:

```text
План месяца → генерация текстов и картинок → Supabase vk_drafts → publish_vk_scheduled.py → VK API
```

Пока VK API не даёт токен с правами `photos`, временный рабочий маршрут публикации:

```text
План месяца → Supabase vk_drafts → publish_vk_playwright_strict.py → VK через браузерную сессию
```

### Шаг 1. Собрать план месяца

```powershell
py -3 tools/build_vk_month_plan.py
```

Результаты:

- `output/vk_month_plan.json`
- `output/vk_month_plan_preview.md`
- `Входящие материалы/vk_topics.json`

### Шаг 2. Подготовить входные JSON для всех дней плана

Без отправки в KIE:

```powershell
py -3 tools/run_vk_month_generation.py
```

Для проверки первых 2 дней:

```powershell
py -3 tools/run_vk_month_generation.py --limit 2
```

Результаты:

- `output/vk-month-inputs/`
- `output/vk-month-generation-commands.ps1`

### Шаг 3. Запустить генерацию черновиков в Supabase

Осторожно: этот шаг отправляет запросы в KIE и генерирует картинки.

```powershell
py -3 tools/run_vk_month_generation.py --send
```

Для теста первых 2 дней:

```powershell
py -3 tools/run_vk_month_generation.py --send --limit 2
```

Каждый готовый пост сохраняется в `Supabase` таблицу `vk_drafts` со статусом `ready` и своим `scheduled_for`.

### Шаг 4. Проверить, что есть готовые черновики к публикации

Без публикации:

```powershell
py -3 publish_vk_scheduled.py --dry-run
```

### Шаг 5. Разовый запуск публикации по расписанию

Через строгий Playwright-режим:

```powershell
py -3 publish_vk_playwright_strict.py --dry-run
py -3 publish_vk_playwright_strict.py --publish
```

Первый вход в VK:

```powershell
py -3 publish_vk_playwright_strict.py --login-only
```

Через VK API, когда будет рабочий `VK_USER_TOKEN` с правом `photos`:

```powershell
py -3 publish_vk_scheduled.py
```

Скрипт публикует только те записи, где:

- `status=ready`
- `publish_channel=vk`
- `scheduled_for` уже наступил
- есть текст и визуал

### Шаг 6. Запуск через планировщик Windows

Для текущего Playwright-режима подготовлен файл:

```powershell
powershell -ExecutionPolicy Bypass -File ".\tools\vk_playwright_publish_once.ps1"
```

Логи пишутся в:

```text
output/logs/vk-playwright-publisher.log
```

Для будущего VK API-режима подготовлен файл:

```powershell
powershell -ExecutionPolicy Bypass -File ".\tools\vk_publish_once.ps1"
```

Его можно поставить в Планировщик заданий Windows, например каждые 10 минут.
Логи пишутся в:

```text
output/logs/vk-publisher.log
```

## 10. Автопубликация в VK через браузер — запасной режим

Этот вариант был тестовым запасным путём.
Основной рабочий путь проекта — через `Supabase`, `publish_vk_scheduled.py` и `VK API`.

### Первый запуск: установка Playwright

```powershell
py -3 -m pip install -r requirements.txt
py -3 -m playwright install chromium
```

### Второй шаг: один раз войти во ВКонтакте

```powershell
py -3 publish_vk_browser_scheduled.py --login-only
```

Откроется браузер. Войдите в VK под админом сообщества. После входа вернитесь в консоль и нажмите `Enter`.

### Публикация готовых черновиков

Безопасный режим с ручной проверкой перед нажатием кнопки публикации:

```powershell
py -3 publish_vk_browser_scheduled.py
```

Полностью автоматический режим:

```powershell
py -3 publish_vk_browser_scheduled.py --auto-click
```

Скрипт берёт записи из `vk_drafts`, где `status=ready`, `publish_channel=vk`, `scheduled_for` уже наступил, есть `post_text` и `image_url`/`video_url`.
