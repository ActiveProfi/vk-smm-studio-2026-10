# Чек-лист агентов и оркестраторов VK

Цель документа: зафиксировать текущую структуру контент-завода VK и понять, какие типы публикаций уже готовы, а какие надо отдельно отработать.

## 1. Общая схема проекта

Сейчас проект строится по цепочке:

1. Тема и исходные материалы.
2. Агент конкретного типа публикации.
3. Проверка фактов и формата VK.
4. Визуальный агент: картинка, обложка, комикс или видео.
5. Сохранение результата в файлы проекта и Supabase.
6. Публикация в VK по расписанию.

Главная мысль: разные типы публикаций нельзя делать одним одинаковым агентом. У каждого формата должен быть свой сценарий, структура, визуальная логика и проверка.

## 2. Центральные оркестраторы

### 2.1. `run_agent.py`

Статус: готов v1, рабочий.

Что делает:

- принимает входной JSON;
- выбирает prompt по `post_type`;
- собирает общий контекст проекта;
- отправляет запрос в KIE/Claude;
- может запускать генерацию картинки через `Nano Banana Pro`;
- может запускать видео через `Veo`, `Hailuo`, `Kling`;
- сохраняет черновик в Supabase `vk_drafts`;
- не ставит `ready`, если нет визуала.

Что надо доработать:

- лучше отделить посты, статьи, обложки и сериалы как разные сценарии;
- добавить более строгую очистку ответа перед сохранением в `vk_drafts`;
- добавить отдельную логику для статей и постов-анонсов.

### 2.2. `tools/build_vk_month_plan.py`

Статус: готов v1.

Что делает:

- берёт список тем из `30 тем Базовые изменения НДС 2026.md`;
- берёт расписание из `configs/vk_schedule_month.json`;
- создаёт месячный план;
- сохраняет `output/vk_month_plan.json`;
- сохраняет предпросмотр `output/vk_month_plan_preview.md`;
- создаёт `Входящие материалы/vk_topics.json`.

Что надо доработать:

- добавить признак: нужна ли к теме статья;
- добавить признак: нужен ли пост-анонс к статье;
- добавить приоритеты тем;
- добавить ручное утверждение плана перед генерацией.

### 2.3. `tools/run_vk_month_generation.py`

Статус: готов v1, но логика форматов пока упрощённая.

Что делает:

- берёт `output/vk_month_plan.json`;
- создаёт входные JSON для каждого дня;
- может запустить `run_agent.py --send --send-image`;
- сохраняет черновики в Supabase со временем публикации.

Важное ограничение:

Сейчас часть форматов из месячного расписания не имеет отдельного агента и временно сводится к базовым типам.

Текущая карта после доработки:

- `expert` → `expert`
- `razbor` → `razbor`
- `serial` → `serial`
- `checklist` → `checklist`
- `case` → `case`
- `humor` → `yumor`
- `calculation` → `calculation`
- `law_review` → `law_review`
- `poll` → `poll`

Что надо доработать дальше:

- для каждого типа генерировать свой входной JSON;
- добавить возможность генерировать связку `статья + обложка + пост-анонс`.

## 3. Агенты текстовых публикаций

### 3.1. Агент `razbor`

Файл: `prompts/razbor.md`

Статус: готов v1, уже применялся на практике.

Формат:

- ситуация;
- что важно по НДС;
- где риск или ошибка;
- что проверить на практике;
- вопрос или мягкий CTA.

Подходит для:

- экспертных разборов;
- объяснения ошибки;
- простых юридических/налоговых тем;
- постов типа “почему нельзя делать так”.

Что уже проверено:

- тема `НДС - коды видов операций`;
- пост с иллюстрацией опубликован в VK.

Что надо улучшить:

- отдельный шаблон для длинного разбора со ссылкой на статью;
- отдельный шаблон для короткого разбора без статьи.

### 3.2. Агент `checklist`

Файл: `prompts/checklist.md`

Статус: prompt готов, полная публикационная цепочка требует теста.

Формат:

- короткий заголовок;
- 5-9 пунктов;
- каждый пункт 1-2 строки;
- вопрос или мягкий CTA.

Подходит для:

- списков проверки;
- “что проверить перед…”;
- памяток;
- инфографик.

Что надо отработать:

- 2-3 тестовых чек-листа;
- визуальный шаблон чек-листа;
- проверку, что пункты не превращаются в длинную статью.

### 3.3. Агент `serial`

Файл: `prompts/serial.md`

Дополнительно:

- `docs/characters/alina.md`
- `prompts/serial-comic-frames.md`

Статус: prompt и персонаж готовы, формат требует практической отработки.

Формат:

- название серии;
- завязка;
- 3-6 коротких сцен или реплик;
- вывод Алины;
- вопрос или тизер следующей серии;
- описание 3-4 кадров для комикса.

Подходит для:

- рубрики “Будни бухгалтера”;
- ситуаций с директором, бухгалтером, контрагентом;
- объяснения сложной темы через маленькую сцену.

Что уже готово:

- образ Алины;
- правила характера;
- правила внешности;
- блок описания кадров.

Что надо отработать:

- сделать первую полноценную серию;
- сгенерировать комикс через `Nano Banana Pro`;
- проверить постоянство образа Алины;
- решить, где нужен комикс, а где короткое видео.

### 3.4. Агент `yumor`

Файл: `prompts/yumor.md`

Статус: prompt готов, публикационная цепочка требует теста.

Формат:

- короткая сценка, диалог или наблюдение;
- после шутки обязательная полезная мысль по НДС;
- вопрос или вовлекающий комментарий.

Подходит для:

- лёгких постов;
- бухгалтерских наблюдений;
- снятия напряжения в сложной теме.

Что надо отработать:

- 3 тестовых юмористических поста;
- границы юмора: без кринжа, грубости и обесценивания бухгалтера;
- визуальный формат: мем-карточка, мини-комикс или короткое видео.

## 4. Форматы из расписания с отдельными агентами

### 4.1. `expert`

Сейчас: есть отдельный prompt `prompts/expert.md`.

Назначение: экспертный пост.

Чем должен отличаться:

- сильный тезис;
- экспертное объяснение;
- меньше сценки, больше уверенной структуры;
- аккуратная оговорка, что материал не заменяет консультацию.

Статус: prompt создан, нужна серия тестовых публикаций.

### 4.2. `case`

Сейчас: есть отдельный prompt `prompts/case.md`.

Назначение: разбор кейса.

Чем должен отличаться:

- исходная ситуация;
- действия участника;
- ошибка или риск;
- правильная логика;
- вывод.

Статус: prompt создан, нужна серия тестовых публикаций.

### 4.3. `calculation`

Сейчас: есть отдельный prompt `prompts/calculation.md`.

Назначение: пример расчёта.

Чем должен отличаться:

- минимум художественности;
- понятные числа;
- пошаговая арифметика;
- особая проверка фактов;
- по умолчанию ставка 22 процента, если не задан другой сценарий.

Статус: prompt создан, нужна особенно строгая проверка фактов и чисел.

### 4.4. `law_review`

Сейчас: есть отдельный prompt `prompts/law_review.md`.

Назначение: разбор нормы закона.

Чем должен отличаться:

- что говорит норма;
- к кому относится;
- где риск неправильного понимания;
- что проверить в документах;
- без самовольных юридических выводов.

Статус: prompt создан, нужна особенно строгая проверка источников.

### 4.5. `poll`

Сейчас: есть отдельный prompt `prompts/poll.md`.

Назначение: пост-вопрос или обычный пост-опрос.

Чем должен отличаться:

- короткая подводка;
- вопрос;
- 3-5 вариантов ответа;
- комментарий после опроса или пост-продолжение.

Статус: prompt создан, нужна проверка публикации как обычного поста с вопросом.

Ограничение: автопубликация настоящего VK-опроса через текущий Playwright/API сценарий ещё не закреплена. На первом этапе можно публиковать обычный пост с вопросом.

Опора:

Опора:

Проверяет:

- нет ли валют, логотипов, эмодзи;
- есть ли `nds04ka.online` маленькой подписью в самом низу визуала;
- правильный формат для VK;
- показывает ли визуал рабочую задачу, риск или проблему;
- приглашает ли визуал к чтению и обсуждению, а не просто украшает пост.

Статус: правило есть, недавно усилено.
