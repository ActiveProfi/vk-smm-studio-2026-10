# Резюме текущего этапа VK

## Что уже работает

- `run_agent.py` собирает текст поста через `KIE`
- `run_agent.py` умеет запускать генерацию картинки через `KIE`
- результаты сохраняются в папку `output/`
- каждый запуск пишется в `Supabase` таблицу `agent_runs`
- готовый черновик поста пишется в `Supabase` таблицу `vk_drafts`
- в `vk_drafts` сохраняются:
  - тема
  - тип поста
  - текст поста
  - входные данные
  - ссылки на файлы результата
  - статус
  - плановая дата и время публикации `scheduled_for`
- правило для `VK` уже зафиксировано:
  - без визуала черновик не может стать `ready`
  - нужен комплект `текст + визуал`
- основной маршрут автопостинга:
  - `Supabase`
  - `publish_vk_scheduled.py`
  - `VK API`
  - пост + картинка

## Что проверено руками

- `Supabase` подключен и запись из `run_agent.py` работает
- `vk_drafts` создается и заполняется
- `scheduled_for` сохраняется
- `VK API` с токеном сообщества отвечает
- `wall.post` через токен сообщества работает для текстового поста
- `VK_USER_TOKEN` добавлен в `.env`
- `VK_USER_TOKEN` получен через сервис `VK Host`, приложение `VK Connect`
- текущий `VK_USER_TOKEN` читается, но пока не проходит `photos.getWallUploadServer`: ошибка `15`, не хватает scope для вызова метода
- письмо в поддержку VK отправлено на `devsupport@corp.vk.com`
- браузерный вариант автопостинга не считаем основным: основной путь остается через `Supabase` и `VK API`

## Что не завершено

- автоматизация запуска на длинный период: массово создать черновики на месяц и регулярно запускать публикацию по расписанию
- проверить диагностикой, что текущий `VK_USER_TOKEN` проходит загрузку картинки через `photos.getWallUploadServer`

## Почему не завершено

- цепочка публикации уже построена вокруг `publish_vk_scheduled.py`
- этот скрипт берет из Supabase только записи:
  - `status=ready`
  - `publish_channel=vk`
  - `scheduled_for <= now`
- для картинки скрипт использует загрузку через `VK API`, поэтому в `.env` должен быть токен, который проходит `photos.getWallUploadServer`

## На чем остановились

- проект уже умеет готовить черновик поста к отложенной публикации
- нужно довести не разовый пост, а месячный конвейер:
  - план на месяц
  - генерация черновиков с визуалом
  - сохранение в Supabase со временем публикации
  - регулярный запуск `publish_vk_scheduled.py`

## Что нужно для завершения

1. Собрать/обновить план месяца.
2. Массово создать входные JSON для агента по каждому дню плана.
3. Запустить генерацию текстов и картинок в `KIE` с сохранением в `vk_drafts`.
4. Проверить один due-черновик диагностикой перед боевым запуском.
5. Поставить регулярный запуск `publish_vk_scheduled.py` через планировщик Windows.

## Важное правило проекта

- для `VK` не публикуем просто текст
- только комплект:
  - текст
  - изображение / инфографика
  - видео / анимация, если выбран видео-формат
