# Шаг 4. Как агент выбирает `image` или `video`

Этот файл нужен для одного простого правила: агент не должен выбирать визуал "на глаз". Он должен принимать решение по понятной схеме.

## 1. Базовое правило

- Если задача требует **структуру, факты, пункты, цифры, чек-лист, сравнение, инфографику**, по умолчанию выбирать `image`.
- Если задача требует **эмоцию, движение, короткую сцену, живой анонс, драматургию**, по умолчанию выбирать `video`.
- Любой визуал должен помогать решить рабочую задачу читателя: понять риск, увидеть ошибку, выбрать проверку или захотеть прочитать разбор. Красивая картинка без практического смысла считается слабым результатом.
- Для сообщества по НДС визуал не должен быть “картинкой ради картинки”. Он должен обещать пользу: чему читатель научится или какую рабочую ситуацию сможет проверить.

## 2. Правило приоритетов

Если тема одновременно полезная и эмоциональная, агент выбирает так:

1. Сначала смотрит, есть ли в материале много точных формулировок и смысловых пунктов.
2. Если да, выбирает `image`.
3. Если смысл можно показать через короткую сцену без перегруза текстом, выбирает `video`.
4. Если есть сомнение, агент предлагает `image` как более безопасный вариант для первой версии.

## 3. Выбор по типу поста

| Тип поста | Визуал по умолчанию | Почему |
| --------- | --------------------- | ------ |
| `expert` | `image` | Экспертный пост обычно держится на тезисах, рисках и понятной структуре |
| `razbor` | `image` | Разбор лучше работает в статике, если визуал показывает конкретную проблему, риск и проверку |
| `case` | `image` | Кейс удобно показывать как цепочку “ситуация → риск → проверка” |
| `calculation` | `image` | Расчёт должен читаться спокойно, без перегруза видео |
| `law_review` | `image` | Нормы и правила лучше показывать через 3-5 коротких блоков |
| `poll` | `image` | Опросу достаточно карточки-вопроса, варианты ответов лучше оставить в тексте |
| `yumor` | `image` или `video` | Если это короткая шутка-сценка — можно `video`; если это мем/ситуация — `image` |
| `serial` | `image` | Для первой версии лучше комикс/серия кадров с Алиной; видео только если сюжет явно требует движения |
| `checklist` | `image` | Чек-лист, инфографика и карусель почти всегда лучше читаются в статике |
| `article_announcement` | `image` | Анонс статьи лучше поддерживать отдельной карточкой или иллюстрацией для ленты |

## 4. Когда точно выбирать `image`

Выбирать `image`, если:

- есть список, шаги, правила, сравнение;
- нужно показать цифры, проценты, лимиты;
- нужно, чтобы пользователь мог остановиться и спокойно прочитать;
- есть риск, что видео перегрузит тему;
- нужен квадрат, карточка, обложка или карусель.

Особенно выбирать `image`, если:

- нужен чистый русский текст без ошибок;
- материал лучше объяснять через инфографику;
- тема держится на пороге, чек-листе, схеме, стрелках, этапах или сравнении;
- нужен стиль, похожий на `NotebookLM`: светлый фон, крупный заголовок, 3-5 смысловых блоков.
- нужно показать рабочую задачу: где ошибка, что проверить, какой документ посмотреть, какой шаг сделать первым.

## 5. Когда точно выбирать `video`

Выбирать `video`, если:

- задача — короткий анонс;
- нужно передать эмоцию, напряжение, сомнение, инсайт;
- это сценка, мини-диалог, реакция, живая ситуация;
- смысл можно донести за 10–30 секунд без длинного текста в кадре.

## 5A. Новое правило: если в видео нужен текст

Если идея ролика держится на тексте внутри кадра, агент не должен сразу отправлять задачу в text-to-video.

Правильная схема:

1. Сначала сделать базовый кадр через `GPT Image 2`
2. На этой картинке разместить короткий текст, который реально должен быть в кадре
3. Только потом использовать эту картинку как основу для video generation

Это особенно важно, если:

- в кадре нужен русский текст;
- нужен заголовок, короткая фраза, подпись или финальный экран;
- текст важен для смысла ролика, а не просто как декоративный элемент.

## 5B. Как выбирать видеомодель

- `Veo 3.1` — когда нужен живой text-to-video без критически важного текста в самом кадре.
- `Hailuo` — когда нужен более управляемый image-to-video сценарий от готовой картинки.
- `Kling 3.0` — когда нужен более постановочный ролик, управляемое движение, либо хотим анимировать заранее подготовленный кадр в формате `9:16`.

Если в ролике важен текст в кадре, по умолчанию безопаснее выбирать маршрут:

1. `GPT Image 2`
2. потом `Hailuo` или `Kling 3.0`

## 5C. Реальные фото из референсов (люди / животные)

Если в референсах канала есть реальные фотографии персонажей:

1. Сначала выбрать **самое подходящее реальное фото** под сцену.
2. Сохранить человека/животное максимально узнаваемым; генеративно менять сцену вокруг.
3. Другой ракурс — только через **другое реальное фото** с нужным ракурсом, не «поворачивать» генерацией.
4. Если подходящего фото нет — не выдумывать лицо: ближайший реальный кадр или сцена без персонажа.

## 6. Стоп-правила

Агент не должен выбирать `video`, если:

- тема требует длинных юридических формулировок;
- в кадре нужен большой объем текста;
- суть держится на таблице, перечне или подробной логике;
- без субтитров или озвучки ролик станет непонятным.

Агент не должен выбирать `image`, если:

- идея строится на эмоции, движении или реакциях;
- пост похож на маленькую сцену, а не на объяснение;
- лучше сработает “живой” короткий хук.

## 7. Формат, который должен вернуть агент

После текста поста агент должен вернуть:

1. `Рекомендация по визуалу`: `image` или `video`
2. `Почему выбран этот формат`
3. `Формат VK`
4. `Промпт для KIE`

## 8. Форматы VK для решения

Если выбрано `image`:

- карточка / обложка: `1:1`
- лента: `4:5`
- редкие вертикальные кадры: `9:16`

Если выбрано `video`:

- по умолчанию: `9:16`
- модель выбирается по задаче: `veo3_fast`, `hailuo/02-image-to-video-pro`, `hailuo/02-text-to-video-pro` или `kling-3.0/video`
- если в ролике нужен текст внутри кадра: сначала `GPT Image 2`, потом image-to-video
- режим v1: короткое объяснение или короткая сценка

## 9. Практическое правило для первой версии агента

Для v1 агент должен быть осторожным:

- если сомневается между `image` и `video`, выбирать `image`;
- `video` использовать только там, где реально есть выигрыш по подаче;
- сериал с Алиной по умолчанию считать статическим комиксом, а не видео.
- если в видео нужен русский текст внутри сцены, не надеяться на text-to-video: сначала строить кадр через `GPT Image 2`.
- если нужен визуал в экспертной подаче как инфографика `NotebookLM`, сначала делать сильную статичную основу, а не гнаться сразу за видео.
